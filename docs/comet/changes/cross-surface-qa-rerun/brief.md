# Outcome

在用户端、管理员端和 HTTP API 已合并的集成基线上重新执行完整跨页面 QA，修复当前验收范围内的阻断性遗漏，并形成诚实、可执行的上线准备结论。

# Scope

- 验证认证、找回密码、工作台、生成模拟、前后对比、作品、额度和订单入口的完整用户流程。
- 验证 `/admin` 管理员授权边界与 Provider 配置页面。
- 覆盖桌面、390px 和 320px 移动视口，检查布局、焦点、语义名称、键盘操作和严重可访问性问题。
- 执行自动化测试、lint、build、typecheck/语法检查及敏感信息检查。
- 更新上线准备报告，区分当前本地 MVP 能力与生产上线仍需完成的事项。
- 只修复验收 A1-A8 范围内的实现或测试遗漏；用户可见行为变化必须返回 Supervisor Shape。

# Non-goals

- 不部署服务器，不配置域名，不远程推送。
- 不接入或执行真实支付交易、真实图像 Provider、真实邮件服务或生产数据库迁移。
- 不写入生产凭据、商户密钥或真实 API 密钥。
- 不把 QA 通过视为发布批准。

# Acceptance examples

- A1: 核心用户流程可从认证进入工作台，完成参数选择、生成模拟、前后对比，并访问作品和额度入口；不存在阻断性页面错误。
- A2: 生成结果的前后对比控件可通过指针和键盘操作，左右两侧标签清晰且不会互相遮挡。
- A3: 关键页面在桌面和移动视口下无横向溢出、文字裁切或主要控件重叠。
- A4: 交互控件具有可见焦点，关键表单与按钮具备可理解的名称，页面不存在自动化可访问性检查发现的严重问题。
- A5: 未登录、普通用户和管理员边界符合现有服务约束；错误信息、公开响应和前端构建产物不包含测试密钥或敏感配置明文。
- A6: 自动化测试、lint、build 和 typecheck/语法检查全部通过，失败项必须记录原因而不能静默忽略。
- A7: 上线准备报告明确区分已就绪能力和未完成的生产数据库、服务器、域名、真实支付、真实 Provider、邮件服务及密钥管理工作。
- A8: 本 Change 不执行部署、远程推送、域名配置、真实支付交易或生产凭据写入。

# Constraints and invariants

- 使用本地环境和模拟数据进行浏览器验证，不绕过服务端认证、额度、订单或管理员权限。
- 密钥、商户资料和生产凭据不得进入源码、文档、日志、截图、Git 或 Comet 状态。
- 保持已确认的邮箱密码登录、额度包规则、生成流程和管理员行为不变。
- 发现新的用户可见决定或验收标准变化时返回 Supervisor Shape，不在本子项中自行扩展范围。

# Decisions

- 本子项严格继承已批准的 Supervisor 拆分，不产生新的产品决定。
- 验证视口固定覆盖桌面、390px 和 320px。
- 当前目标是本地付费 MVP 的集成质量与上线准备评估，不是生产发布。

# Open questions

- 无。父级批准范围已完整覆盖本子项。

# Verification expectations

- `npm test`
- `npm run lint`
- `npm run build`
- `npm run typecheck`
- `npm run qa:browser`
- 浏览器检查认证恢复、生成与前后对比、作品与额度/订单、`/admin` 权限与 Provider 管理。
- 对源码、公开响应和构建产物进行敏感信息与权限边界检查。
- 独立只读 Verifier 逐项核对 A1-A8。
