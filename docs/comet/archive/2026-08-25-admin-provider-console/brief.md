# Outcome

为管理员提供可控、可审计的 Provider 配置管理能力，为后续接入真实 Provider 保留安全边界。

# Scope

- 管理员身份和权限校验。
- Provider 配置的新增、查看、修改、启用和停用。
- 密钥只允许写入，不回显明文；界面、错误信息和日志统一脱敏。
- 配置采用加密存储边界，业务代码只接触受控的配置接口。
- 记录配置变更审计事件。

# Non-goals

- 不接入真实支付平台或生产 Provider。
- 不配置服务器、域名、生产凭据或部署上线。
- 不实现普通用户的 Provider 配置管理。
- 不在本 Change 引入生产数据库或正式密钥管理服务。

# Acceptance examples

- A1: 未登录用户和非管理员访问 Provider 配置接口或页面时被拒绝，且不泄露配置内容。
- A2: 管理员可以创建、查看脱敏配置、修改、启用和停用 Provider；配置状态变化可被观察。
- A3: Provider 密钥在读取响应、页面、错误信息、日志和审计记录中都不会出现明文或可逆拼接片段。
- A4: Provider 配置写入和读取经过统一加密存储边界，业务层不直接读取明文持久化值。
- A5: 每次创建、修改、启用、停用操作都会产生包含管理员、Provider、动作和时间的审计记录，且不包含密钥明文。
- A6: 管理员只能操作当前授权范围内的 Provider 配置，越权访问和越权修改均失败且不改变配置。
- A7: 自动化测试覆盖权限拒绝、配置生命周期、密钥不回显、脱敏、加密边界、审计和用户隔离。

# Constraints and invariants

- 当前实现使用内存存储；不得把真实凭据写入源码、文档、日志、测试夹具或 Git。
- 配置默认停用，只有明确启用后才允许被后续 Provider 调用边界读取。
- 删除或停用配置不得删除审计历史。
- 失败的越权操作不得产生可用配置变更。

# Decisions

- 登录体系沿用邮箱和密码会话；管理员权限在现有会话基础上判定。
- 本 Change 采用 branch 隔离，完成后合并回 master。
- 生产数据库、真实密钥管理和 Provider 接入属于后续部署/生产 Change。

# Open questions

- 无。当前范围内未保留待用户决定的问题。

# Verification expectations

- npm test
- npm run lint
- npm run build
- npm run typecheck
- 独立只读 Verifier 逐项检查 A1-A7，并确认没有敏感凭据进入源码、文档、日志或 Git。
