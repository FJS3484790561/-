# Outcome

为 AI 室内设计师建立可安全恢复的邮箱账号与会话基础，支持用户注册、登录和找回密码，为后续用户作品、额度和订单隔离提供身份边界。

# Scope

- 邮箱 + 密码注册。
- 邮箱 + 密码登录和退出。
- 通过邮箱发送一次性密码重置链接，并设置新密码。
- 用户会话建立、恢复和失效。
- 未授权访问返回安全的未登录结果。
- 为后续用户级资源访问提供稳定的用户身份标识。

# Non-goals

- 支付、额度、充值套餐和退款。
- AI 生成、Provider 调用和图片存储。
- 作品库、管理员配置和多角色权限。
- 第三方登录、手机号登录和团队账户。
- 生产邮件供应商选型与部署。

# Acceptance examples

- A1: 用户提交合法邮箱和密码后，可以创建账号；重复邮箱被拒绝并显示可理解错误。
- A2: 已注册用户可以登录和退出；错误密码不会建立会话。
- A3: 用户请求密码重置后，系统不会泄露邮箱是否存在，并对有效请求生成一次性、限时重置流程。
- A4: 有效重置链接只能使用一次；过期或已使用链接不能修改密码。
- A5: 登录会话在刷新后可以恢复，退出后旧会话不能继续访问受保护资源。
- A6: 未登录用户访问受保护用户资源时得到未授权结果；用户只能以自己的身份访问后续资源边界。

# Constraints and invariants

- 密码只能以不可逆哈希保存，禁止明文、URL、日志和普通响应泄露。
- 重置令牌只能保存不可逆摘要，限时、一次性使用并具备频率限制。
- 会话使用 HttpOnly、SameSite Cookie；生产环境启用 Secure。
- 错误信息不得暴露用户是否注册或内部堆栈。
- 所有身份与会话状态必须由服务端权威维护。
- 本 Change 不实现额度、支付、生成或作品业务规则。

# Decisions

- 使用邮箱 + 密码登录，支持邮箱找回密码。
- MVP 不接入手机号或第三方登录。
- 单一普通用户身份边界先满足个人作品跨设备使用；组织和多角色后置。
- 这些决定已在项目规格和路线图中由用户确认。

# Open questions

- 生产邮件服务商和域名由后续部署 Change 确定，不阻塞本 Change 的可测试邮件抽象。
- 具体生产密码策略和保留周期需在上线安全审查中确认。

# Verification expectations

- 运行 lint、build 和相关单元/集成测试。
- 测试注册、重复邮箱、登录成功/失败、退出、重置链接成功/过期/重复使用和未授权访问。
- 检查日志、响应和浏览器存储不含密码或重置令牌明文。
- 由独立只读 Verifier 对全部 A1-A6 逐项验收。
