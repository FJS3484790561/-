# Outcome

完成付费 MVP 的用户网页 Surface：用户可通过邮箱认证进入设计工作台，并通过本地 HTTP API 完成生成、前后对比、作品、额度与充值订单等核心流程。

# Scope

- 新增登录、注册、忘记密码与重置密码界面，并接入 `/api/auth/*`。
- 将现有工作台的上传、参数选择、生成任务与查询结果接入 `/api/generations`，保留可键盘操作的前后对比滑块。
- 新增我的作品列表与详情/空状态，接入 `/api/works`。
- 新增额度与充值界面，展示余额及小额自定义、10 元 12 次、30 元 45 次、100 元 200 次方案，并接入 `/api/credits` 与 `/api/orders`。
- 新增账户菜单、退出登录和帮助/隐私入口。
- 保持 UI Lock 的粘土拟态视觉、桌面/移动布局、焦点与 reduced-motion 规则。

# Non-goals

- 不实现管理员 Provider 页面。
- 不接入真实支付、真实图像 Provider、生产邮件、数据库、对象存储、服务器或域名。
- 不在浏览器中保存管理员凭据、Provider 密钥或支付签名。
- 不改变已确认的额度包、认证、生成、订单或数据隔离业务规则。

# Acceptance examples

- A1: 未登录用户看到认证界面；可注册、登录、退出、请求密码找回，错误信息安全且登录后会话可恢复。
- A2: 已登录用户可上传有效图片、选择空间/风格/强度/偏好并通过 HTTP API 创建生成任务；加载、失败、额度不足和成功状态均可见且可恢复。
- A3: 成功结果同时展示原图与效果图，前后对比滑块可通过指针和键盘操作，标签清晰且下载/保存动作状态正确。
- A4: 我的作品支持空状态、列表、查看单项和保存生成结果；任何用户都不能通过界面读取其他用户作品。
- A5: 额度页展示当前余额、有效期说明和已确认充值方案；创建订单后只显示待支付状态，不虚构支付成功或提前增加额度。
- A6: 关键用户页面在桌面和 320-390px 移动视口无横向溢出、文字裁切或主要控件重叠，焦点可见、表单有名称、主要目标至少 44px。
- A7: 浏览器请求统一使用本地 HTTP API 和 HttpOnly 会话 Cookie；前端源码、错误信息和构建产物不包含会话令牌、测试密钥或敏感配置明文。
- A8: 用户端自动化测试、lint、build、typecheck/语法检查通过，并提供桌面与移动浏览器验证证据。

# Constraints and invariants

- 严格继承 Supervisor `cross-surface-qa-release-readiness` 的 A1、A3、A4、A5 范围。
- 维持 UI_LOCK_VERSION 1.0；本次结构增补已由用户批准，不改变锁定视觉方向。
- Cookie 身份是唯一浏览器会话来源，不在 localStorage 或请求体中持久化/发送 sessionToken。
- 生成一次消耗一点额度；失败不扣额度；支付回调前订单不得增加额度。
- 当前 Store 和 Provider 均为本地实现，UI 必须诚实呈现，不宣称生产可用。

# Decisions

- 用户端使用同一 React 应用中的明确页面/视图导航，工作台仍是登录后的首要页面。
- 认证方式为邮箱和密码，并提供邮箱找回密码流程。
- 充值方案沿用已确认规则：10 元以下充多少得多少次，10 元 12 次，30 元 45 次，100 元 200 次。
- UI_CHANGE_PERMISSION: APPROVED；用户已批准新增缺失用户页面及页面结构。
- 本子 Change 由已确认 Supervisor Shape 严格派生，无新增用户可见决策。

# Open questions

- 无。目标、范围、关键决定、验收项和非目标均继承已确认 Supervisor 与 UI Lock。

# Verification expectations

- npm test
- npm run lint
- npm run build
- npm run typecheck
- 使用本地 HTTP Server 与前端预览验证认证、生成、作品、额度和退出流程。
- 使用 Playwright 检查桌面与 390px/320px 移动视口、键盘焦点、对比滑块、控制台错误与布局溢出。
- 独立只读 Verifier 逐项核对 A1-A8，并检查源码和构建产物的敏感信息边界。
