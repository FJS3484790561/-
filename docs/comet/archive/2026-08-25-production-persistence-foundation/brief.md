# Outcome

将当前进程内账户、会话、Provider 配置、额度、订单、作品和生成记录迁移到可事务化、可迁移、可备份恢复的生产持久化底座，并建立图片对象存储边界，使服务重启不再丢失业务数据。

# Scope

- 为现有服务提供统一持久化数据库、版本化迁移和事务边界。
- 持久化账户、会话、Provider 配置、额度批次与流水、订单与回调状态、作品和生成记录。
- 建立图片对象存储接口、生产适配配置和本地测试适配器，数据库只保存对象引用及必要元数据。
- 提供脱敏的数据库备份、恢复和恢复后完整性检查流程。
- 保持现有 HTTP API 和前端可见行为兼容，为后续邮箱、额度码、生图和支付子 Change 提供数据接口。

# Non-goals

- 不接入真实邮件、微信支付商户、真实生图 Provider、域名或腾讯云生产环境。
- 不实现邮箱验证、注册开关、额度码业务规则或新的用户页面。
- 不执行生产部署、真实数据迁移、真实扣款或发布。

# Acceptance examples

- A1: 创建账户、会话、Provider 配置、额度、订单和作品后重启应用，数据仍可读取且关联关系保持一致。
- A2: 额度增加、成功生成扣减和支付到账使用事务及唯一约束，失败或重复操作不会造成部分写入、负余额或重复到账。
- A3: 图片内容通过对象存储接口写入和读取，数据库只保存对象键、类型、大小和归属等元数据；本地测试不需要生产凭据。
- A4: 数据库迁移可从空库重复执行到最新版本；备份可恢复到隔离位置，完整性检查能核对关键表、外键和额度流水一致性。
- A5: 未配置生产数据库或对象存储时采用明确的非生产配置；生产模式缺少必要配置必须拒绝启动，不得静默退回内存存储。
- A6: 现有自动化测试保持通过，并新增重启持久化、事务回滚、并发幂等、迁移、对象存储和备份恢复测试。

# Constraints and invariants

- 服务端数据库是账户、会话、额度、订单、作品和配置状态的权威来源。
- 额度批次保留来源、到账时间、到期时间和不可变流水；默认到期规则由调用方提供，本子 Change 不新增业务发放规则。
- 生产凭据和个人数据不得进入源码、迁移文件、测试夹具、日志、备份清单或 Comet 产物。
- 数据文件、对象存储测试目录和备份产物不得提交 Git。

# Decisions

- DECISION: 继承 Supervisor 已确认的 A1、A20、A33、A34，不改变用户可见额度、支付或生成规则。
- IMPLEMENTATION_CHOICE: 首期单实例生产数据库采用 SQLite WAL 和严格事务/约束，以满足月预算 300 元以内；数据访问边界保持可迁移，不把 SQLite 特性暴露给 HTTP API。
- IMPLEMENTATION_CHOICE: 图片使用对象存储接口；开发与测试使用本地文件适配器，生产适配器通过环境配置接入腾讯云对象存储，浏览器不接触存储凭据。

# Open questions

- 无。该子范围严格继承已批准的 Supervisor Shape。

# Verification expectations

- 使用隔离临时目录和数据库完成真实进程重启测试，不以内存对象复用代替。
- 验证迁移、事务回滚、并发幂等、备份恢复和对象引用归属。
- 运行服务端测试、lint、构建及敏感信息检查；不要求生产凭据或真实云资源。
