# Outcome

完成付费 MVP 当前代码基线的跨页面 QA，并补齐验证发现的浏览器 Surface 与 HTTP API 集成缺口；作为 Supervisor Change 协调子 Change，最后形成可执行的上线准备结论。

# Scope

- 检查首页、认证、工作台、生成结果、前后对比、作品、额度充值和管理员 Provider 配置相关流程。
- 验证桌面端和移动端响应式表现。
- 检查键盘操作、焦点可见性、语义标签和基础可访问性。
- 检查登录态、权限隔离、错误信息和敏感信息边界。
- 执行自动化测试、lint、构建和类型/语法检查。
- 生成上线准备报告，列明已通过项、阻塞项、风险和生产上线前任务。
- 提供连接现有认证、生成、作品、额度、订单和管理员服务的本地 HTTP API 边界。
- 实现认证/找回密码、作品、额度充值、账户帮助和管理员配置页面，并接入 HTTP API。
- 在子 Change 集成完成后重新执行跨页面 QA。

# Non-goals

- 不部署服务器或配置域名。
- 不接入真实支付平台或生产 Provider。
- 不写入生产凭据、商户密钥或真实 API 密钥。
- 不执行数据库迁移、正式发布或远程推送。
- 不把当前内存 Store 宣称为生产持久化，也不接入真实邮件、支付或图像 Provider。

# Acceptance examples

- A1: 核心用户流程可从认证进入工作台，完成参数选择、生成模拟、前后对比，并访问作品和额度入口；不存在阻断性页面错误。
- A2: 生成结果的前后对比控件可通过指针和键盘操作，左右两侧标签清晰且不会互相遮挡。
- A3: 关键页面在桌面和移动视口下无横向溢出、文字裁切或主要控件重叠。
- A4: 交互控件具有可见焦点，关键表单与按钮具备可理解的名称，页面不存在自动化可访问性检查发现的严重问题。
- A5: 未登录、普通用户和管理员边界符合现有服务约束；错误信息、公开响应和前端构建产物不包含测试密钥或敏感配置明文。
- A6: 自动化测试、lint、build 和 typecheck/语法检查全部通过，失败项必须记录原因而不能静默忽略。
- A7: 上线准备报告明确区分已就绪能力和未完成的生产数据库、服务器、域名、真实支付、真实 Provider、邮件服务及密钥管理工作。
- A8: 本 Change 不执行部署、远程推送、域名配置、真实支付交易或生产凭据写入。

# Constraints and invariants

- 不得把密钥、商户资料或生产凭据写入源码、文档、日志、截图、Git 或 Comet 状态。
- 浏览器验证使用本地环境和模拟数据，不代表真实支付或 Provider 可用。
- 发现阻断性缺陷时可在本 Change 内修复；改变已确认产品行为或验收标准时必须返回 Shape。
- 生产发布仍需要独立的 release approval，QA 通过不等于批准上线。
- 子 Change 必须保持现有业务规则，不得以浏览器 mock 绕过服务端认证、额度、订单或管理员权限。

# Decisions

- 覆盖桌面端和移动端核心流程。
- 当前只验证和修复本地付费 MVP 基线，不配置生产基础设施。
- 完成后继续使用 merge 收尾到 master，不推送远程仓库。
- UI_CHANGE_PERMISSION: APPROVED。用户于 2026-08-25 明确批准新增缺失用户页面、管理员页面和相应页面结构。
- 当前 Change 转为 Supervisor；HTTP API 先行，用户端与管理员端可并行，最终 QA 子 Change 在二者合并后执行。

# Open questions

- 无。当前范围内未保留待用户决定的问题。

# Verification expectations

- npm test
- npm run lint
- npm run build
- npm run typecheck
- 使用 Playwright 检查桌面端和移动端核心流程、前后对比控件、控制台错误与关键布局。
- 对源码和构建产物执行敏感信息模式检查，并由独立只读 Verifier 逐项核对 A1-A8。
- 每个子 Change 独立 Build/Verify，并合并回 Supervisor 分支；Supervisor 最终再次验证完整 A1-A8。
